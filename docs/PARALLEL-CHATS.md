# Два чата в одном репозитории

## Зачем это записано

Владелец ведёт несколько разговоров одновременно: один правит интерфейс,
другой — движение, третий разбирает обучение. Все они работают с одним
репозиторием, и однажды это столкнулось: пока один чат дописывал
`CommandPalette.tsx`, второй прогонял проверку типов и получил пять ошибок
в чужом наполовину написанном файле. Ошибки были настоящие, но не его,
и чинить их означало бы затереть чужую работу.

## Почему одних веток мало

Ветка не изолирует. Ветки живут в **одном** рабочем каталоге: переключение
меняет файлы на диске под тем, кто в них сейчас пишет. Два чата на двух
ветках в одном каталоге мешают друг другу сильнее, чем два чата на одной.

Изолирует **рабочий каталог**. Git умеет держать несколько каталогов на
один репозиторий — `git worktree`. История общая, файлы разные.

## Как устроено сейчас

| Каталог | Ветка | Кто там |
|---|---|---|
| `d:/серч` | `main` | основной чат |
| `D:/serch-photos` | `chat-photos` | второй чат |

Каталог второго назван латиницей намеренно. Кириллица в пути уже однажды
сломала загрузку шрифта: Vite в режиме разработки отдавал адрес вида
`/@fs/D:/ÑÐµÑÑ/...`, файл не находился, и весь текст молча рисовался
запасным системным шрифтом.

## Как завести ещё один

```
git worktree add -b <имя-ветки> "D:/serch-<имя>" main
cd "D:/serch-<имя>" && bun install
```

Зависимости ставятся заново — свои `node_modules` на каталог. Это около
полминуты и полтора гигабайта; общие `node_modules` через ссылку не
годятся, рабочие пространства bun разрешаются по пути.

## Как свести обратно

```
git checkout main && git merge <имя-ветки>
git worktree remove "D:/serch-<имя>"
git branch -d <имя-ветки>
```

Сводить лучше **часто и мелкими порциями**: две недели раздельной работы
над одними экранами дадут конфликт, который дешевле переписать, чем
разрешить.

## Правила, без которых это не работает

**Свои файлы — свои коммиты.** Увидели чужие правки в `git status` —
не добавляйте их «заодно». Ставьте в коммит перечисленные пути, а не `-A`.

**Чужие поломки не чините.** Ошибка типов в файле, который вы не трогали,
почти наверняка означает, что его прямо сейчас пишут. Скажите об этом
в отчёте и работайте дальше.

**Демонстрация выкладывается с `main`.** `bun run demo:publish` собирает
то, что лежит в текущем каталоге, — с ветки уйдёт незаконченное.
